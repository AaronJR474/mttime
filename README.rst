MTtime workflow fork
====================

MTtime (Time Domain Moment Tensor Inversion in Python) is an open-source package
for time-domain inversion of complete seismic waveforms. It supports deviatoric
and full moment-tensor inversions and can work with 1-D or externally generated
3-D Green's functions.

This repository remains a fork of the `LLNL MTtime project
<https://github.com/LLNL/mttime>`_. The upstream core API is intentionally kept
recognizable. The principal additions currently live in ``mttime.workflows`` and
provide reproducible waveform preparation, Green's-function preparation and
higher-level inversion orchestration. The fork is not presented as a replacement
or independent reimplementation of upstream MTtime.

What this fork adds
-------------------

``mttime.workflows.mttime_helpers``
    A high-level workflow from station/waveform acquisition through response
    removal, ZRT rotation, Green's-function generation, ``mtinv.in`` writing,
    inversion, timing/resampling studies and tabular/figure outputs.

``mttime.workflows.gf_helpers``
    Velocity-model utilities for fixed 1-D layered models and for extracting
    station- or path-specific 1-D profiles from tabular 3-D velocity models before
    PyFK calculation. A sampled 3-D model is therefore used to construct local
    layered PyFK models; this helper does not turn PyFK into a full 3-D solver.

Green's-function backends
    PyFK is the default local layered-Earth backend on Linux/WSL. EarthScope
    Syngine is also supported and does not require PyFK. MTtime's existing core
    support for externally generated tensor/3-D Green's functions remains
    available.

Helper-managed figures
    ``run_mttime_inversion(..., plot_views=...)`` accepts ``"waveform"``,
    ``"depth"``, ``"map"``, ``"lune"`` and ``"cmt"``. The ``"cmt"`` view is
    generated by ``plot_cmt_summary`` from the preferred MTtime solution.

Core numerical improvement
    The weighted normal equations in ``mttime.core.inversion`` are evaluated by
    row scaling (``w * d`` and ``w[:, None] * G``) instead of explicitly building
    the dense diagonal matrix ``diag(w)``. The algebra is unchanged, while the
    temporary dense ``N x N`` weight matrix is eliminated.

Installation from Git
---------------------

This fork currently declares Python 3.8--3.12 support. For the supported PyFK path, use Linux or WSL. A normal VCS
installation installs MTtime, the workflow dependencies and PyFK automatically:

.. code-block:: bash

   python -m pip install "git+https://github.com/AaronJR474/mttime.git"

The released PyFK package supports the older Python range. For Python 3.10--3.12,
this fork currently pins the Python-3.10+ PyFK update from upstream PR #20 to the
specific commit recorded in ``setup.py``. That PR is not yet merged, so this pin
is deliberately visible and should be replaced by an official PyFK release once
one is available.

Syngine-only / no-PyFK installation
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Native Windows and macOS installations do not automatically request PyFK in this
fork; the Syngine backend and the rest of MTtime can therefore be installed
without it. On Linux/WSL, explicitly suppress the default PyFK dependency with:

.. code-block:: bash

   MTTIME_NO_PYFK=1 python -m pip install "git+https://github.com/AaronJR474/mttime.git"

``MTTIME_NO_PYFK`` is a fork-specific installation switch, not a standard pip
"negative extra". It only changes dependency metadata during this VCS build; it
does not disable any MTtime code. Calling ``generate_pyfk_gfs`` without PyFK
installed will still fail normally at the lazy PyFK import, whereas Syngine does
not import PyFK.

Map plotting
~~~~~~~~~~~~

Cartopy remains optional. Install the map extra when native MTtime map figures are
needed:

.. code-block:: bash

   python -m pip install "mttime[maps] @ git+https://github.com/AaronJR474/mttime.git"

Basic usage
-----------

The upstream core interface is unchanged:

.. code-block:: python

   import mttime

   config = mttime.Configure(path_to_file="mtinv.in")
   inversion = mttime.Inversion(config=config)
   inversion.invert()
   inversion.write()

The additive workflow modules are importable after the same Git installation:

.. code-block:: python

   from mttime.workflows import gf_helpers, mttime_helpers

A typical helper-managed inversion ends with:

.. code-block:: python

   mtinv_stations, inversion, solution_df, station_fit_df, outputs = (
       mttime_helpers.run_mttime_inversion(
           event_df,
           station_df,
           gf_manifest,
           output_file="event/mtinv.in",
           path_to_data="event/processed/data",
           path_to_green="event/greens",
           degree=6,
           plot_views=("waveform", "depth", "map", "lune", "cmt"),
           show=False,
       )
   )

See ``docs/source/workflows.rst`` for the backend contracts, 1-D/3-D model
handling, Syngine route and output conventions.
